# C++ 线程池

## 概念

线程池是一组预先创建并长期运行的工作线程。调用方把任务提交到队列，工作线程从队列中取任务并执行。它避免了为每个任务反复创建和销毁线程的成本。

本仓库示例位于 `include/hpc/cpu/thread_pool.h`、`src/cpu/thread_pool.cpp` 和 `cpu/thread_pool_demo/`。`hpc::ThreadPool` 使用固定数量的 `std::thread`、互斥锁、条件变量和 FIFO 任务队列，`submit()` 返回 `std::future<T>` 获取结果或异常。

## 解决的问题

- 降低短任务频繁创建线程的开销。
- 控制并发数量，避免线程过多导致上下文切换和资源耗尽。
- 统一管理任务提交、等待、异常传递和关闭流程。
- 提高多核 CPU 利用率，适合把大任务拆分为多个子任务。

## 特点

- 工作线程数量通常固定，常按 CPU 核数或业务瓶颈配置。
- 任务通过队列解耦生产者和消费者。
- `future` 可以让调用方同步获取返回值。
- 析构时需要停止接收任务、唤醒线程并 `join`。

## 优势

- 降低线程生命周期管理成本。
- 并发度可控，系统吞吐更稳定。
- 对批量 CPU 计算、异步任务、流水线处理很友好。
- 可以扩展优先级队列、任务统计、CPU 亲和性、限流等能力。

## 劣势

- 任务粒度过小会被队列锁、调度和 `future` 成本抵消。
- 任务中阻塞 I/O 过多会占住工作线程，降低 CPU 任务吞吐。
- 固定线程数不一定适合所有负载，需要压测调参。
- 任务之间如果互相等待，可能产生死锁或线程池饥饿。

## 典型应用

- 图像分块处理、矩阵分片计算、批量特征提取。
- 后台日志压缩、数据预处理、批量文件扫描。
- 服务端请求中的 CPU 密集型子任务。
- 与内存池组合，用于高频任务对象的复用和并发执行。

## 使用建议

CPU 密集型任务通常从 `std::thread::hardware_concurrency()` 附近开始调参；I/O 密集型任务可适当增加线程数。避免在线程池任务里等待同一个线程池的其他任务完成。提交任务前明确任务粒度，优先批量化小任务。

```cpp
hpc::ThreadPool pool(4);
auto result = pool.submit([] { return 42; });
std::cout << result.get() << '\n';
```
