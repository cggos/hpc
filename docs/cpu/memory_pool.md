# C++ 内存池

## 概念

内存池是一种内存管理技术：程序预先向系统申请一大块内存，再按固定大小或特定策略切分成小块，后续对象创建和销毁优先从池中分配和归还，而不是频繁调用 `new/delete` 或 `malloc/free`。

本仓库示例位于 `include/hpc/cpu/memory_pool.h`、`src/cpu/memory_pool.cpp` 和 `cpu/memory_pool_demo/`。其中 `FixedBlockPool` 管理固定大小块，`ObjectPool<T>` 在其上封装对象构造、析构和 RAII 归还。

## 解决的问题

- 降低频繁动态分配带来的系统调用和锁竞争开销。
- 减少堆碎片，提升长时间运行程序的内存稳定性。
- 改善缓存局部性，让相同类型对象更集中地分布。
- 让对象生命周期更可控，便于批量释放或复用。

## 特点

- 分配路径短：通常只是从空闲链表取出一个块。
- 释放路径短：通常只是把块放回空闲链表。
- 适合同类型、固定大小、频繁创建销毁的对象。
- 容量通常需要提前规划，池满后要么抛异常，要么回退到系统堆。

## 优势

- 性能更稳定，避免普通堆分配在高并发或高频场景下抖动。
- 可预测性更强，适合实时计算、游戏、交易、图像处理等场景。
- 便于统计容量、占用率和峰值使用量。

## 劣势

- 实现复杂度高于直接使用标准容器和智能指针。
- 固定块池可能浪费内存，尤其对象尺寸差异较大时。
- 如果对象未正确析构或重复归还，会产生严重内存错误。
- 多线程访问时需要额外同步，否则不是线程安全的。

## 典型应用

- 粒子系统、物理对象、网络连接对象、消息包。
- 高频任务中的临时对象，如图像块、矩阵块、日志事件。
- 对延迟敏感的 CPU 服务，例如实时推理、行情处理、音视频处理。

## 使用建议

优先从简单固定块池开始，明确对象类型、容量和生命周期。对跨线程使用的池增加互斥锁、无锁队列或线程本地池。不要把内存池作为默认优化手段；只有在分析确认分配开销明显时再引入。

```cpp
hpc::ObjectPool<Particle> pool(1024);
auto particle = pool.make_unique(1, 2.0f);
```
